# Background Job Feature
后台任务功能，主要是在后台进行一些AI相关的操作，能够定时获取到基金相关的的信息，并将这些信息存储到localStorage中，以便在界面上展示给用户。比如，基金相关市场的节假日提醒，交割日提醒等。

## 信息存储
在基金Ticker中增加一个字段，叫做info_list，存储基金相关的信息列表。这个字段是一个列表，其中每一个都是一个对象，包含以下内容：
* type：信息的类型，比如节假日信息，交割日信息等。
* date：信息的生效日期，比如节假日的日期，交割日的日期等。
* content：信息的内容，比如节假日的名字，交割日的相关说明等。

后台任务会定时更新这个字段里的信息。

## 界面显示
如果基金的info_list字段里有信息，在这些信息中找出生效日期在当前日期之后的3天以内的信息。如果有这样的信息，就在基金card上显示一个小图标，提示用户有相关的信息需要注意。图标位于基金card的右上角，位置在风险评级图标的右边。用户将鼠标悬停在这个图标上时，会显示一个tooltip，里面列出这些相关的信息的内容和生效日期。信息按照生效日期进行排序，最近的日期排在最前面。用bullet point的形式来展示这些信息。

后台任务对基金的info_list字段进行更新时，会触发这个检查，并对基金card上的图标进行更新。比如，如果之前没有相关的信息，基金card上没有这个图标，当后台任务更新了info_list字段，并且有相关的信息时，就会在基金card上显示这个图标。反之，如果之前有相关的信息，基金card上有这个图标，当后台任务更新了info_list字段，并且没有相关的信息时，就会在基金card上隐藏这个图标。

## 后台任务
后台任务和目前系统中其他定时任务一样，由统一的调度器来管理。后台任务会定时调用AI功能，获取系统内所有基金的相关信息，并将这些信息更新到基金的info_list字段中。更新按照信息的类型来进行增加，修改或删除。简单一点来说就是以信息的类型为key来更新。每个后台任务都对应一个信息类型x。
* 如果获取到基金A的信息，则在A的info_list字段里，找到type为x的信息，如果找到了，就更新这个信息的date和content；如果没有找到，就在info_list里增加一个新的对象，包含type为x，date和content。
* 如果没有获取到基金A的信息，则在A的info_list字段里，找到type为x的信息，如果找到了，就删除这个信息；如果没有找到，就不做任何操作。

### 节假日信息
* 后台任务信息类型：holiday
* AI提示词
```text
请以Json形式列出下列基金（包括其底层标的物及所在市场）的最近（10天以内）的相关市场的节假日信息。

分析步骤：
1. 首先根据基金代码和名称，判断其底层资产主要投向哪个/哪些市场（如中国A股、香港、美国等）。对于QDII基金，需明确其跟踪的指数或投资区域。
2. 然后查询该市场在最近60天内的节假日休市安排。
3. 每个基金只显示一条最近的记录。

字段要求：
- code: 基金代码
- holiday_date_start: 节假日开始日期 (yyyy/MM/dd)
- holiday_date_end: 节假日结束日期 (yyyy/MM/dd)
- holiday_name: 节假日名称
- explanation: 包含节假日起止时间、节假日名称及所属市场

基金列表：
{code_list}
```
其中，code_list是系统内所有基金的代码列表。

* 信息对象填充：
  * type: "holiday"
  * date: AI获取到的最近的节假日的开始日期（holiday_date_start）
  * content: AI获取到的节假日的相关说明（explanation）
### 交割日信息
* 后台任务信息类型：delivery
* AI提示词
```text
请以Json形式列出下列基金（包括其底层标的物及所在市场）的最近交割日。

分析步骤：
1. 首先根据基金代码和名称，判断该基金的类型（如普通开放式基金、ETF、ETF联接、商品期货ETF、QDII等），并识别其底层资产主要投向（如股票指数、商品期货、ETF期权等）。
2. 对于本身有交割日概念的基金（如ETF期权合约、期货合约等），查询其最近的具体交割日期。
3. 对于普通基金，若其底层标的物（如作为期权标的的ETF）有交割日，则注明该底层标的物的最近交割日；若无，则返回null。
4. 每个基金只显示一条最近的交割日记录。

字段要求：
- code: 基金代码
- delivery_date: 最近交割日 (yyyy/MM/dd)，若无则为null
- explanation: 无需解释交割日的判断依据，如有交割日，直接显示交割日期及交割规则，无需显示基金名称

基金列表：
{code_list}
```
其中，code_list是系统内所有基金的代码列表。
* 信息对象填充：
  * type: "delivery"
  * date: AI获取到的最近的交割日（delivery_date）
  * content: AI获取到的交割日的相关说明（explanation）


## 实现细节
