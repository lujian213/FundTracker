# AI Assistant Feature

## AI助手
AI助手可以利用AI提供对特定基金的信息（包括新闻，最近此基金的收益/损失情况）搜集和整理，以及要关注的风险和机会。

### 界面入口
* 在主界面右上角的下拉菜单里增加“AI配置”菜单项，放在同步配置下面。点击打开AI配置窗口。
* 在基金的详情页的工具栏增加一个“AI助手”图标，点击打开AI助手窗口。

### AI配置窗口
可以显示和编辑大模型的相关配置，每个配置组件包括以下内容：
* 模型名称：模型的名称，用户可以自行输入。
* 模型地址：模型的API地址，用户可以输入或修改。
* API-Key：模型的API Key，用户可以输入或修改。
* 是否激活：一个开关，用户可以选择是否激活这个模型。只有当模型被激活时，系统才会使用这个模型来提供AI助手的功能。只能存在一个被激活的模型（配置组），如果用户激活了一个模型，之前被激活的模型会自动被取消激活。

用户可以增加或删除配置组。

#### 实现细节
* 配置数据保存在localStorage中，用户的修改，在确认后会被保存。
* API-Key在显示的时候要mask。
* AI配置信息不参与备份和恢复。导出备份时不包含AI配置数据，导入备份时不修改已有的AI配置。
* 系统预先准备几个常用的模型配置模板，放在一个配置文件中（不包含API-Key），如果localStorage中，没有AI配置数据，系统会自动读取这个配置文件中的模板，并将这些模板加载到localStorage中，供用户选择和修改。

### AI助手窗口
AI助手窗口是一个聊天窗口。
* 如果用户没有配置好AI模型，或者没有激活的AI模型，窗口里会显示提示信息，引导用户去AI配置窗口进行配置和激活。此时，信息发送按钮是不可用的。
* 打开窗口时，自动使用预先配置好的提示词模板，向AI模型发送请求，获取关于当前基金的相关信息，并在窗口里显示出来。用户可以在窗口里输入问题，AI助手会根据用户的问题，结合当前基金的信息，向AI模型发送请求，并将AI模型的回答显示在窗口里。
* 每个基金都有一个独立的AI助手窗口，用户在不同基金的详情页点击AI助手图标，打开的都是对应基金的AI助手窗口。每个窗口里显示的信息都是针对当前基金的。
* AI助手窗口打开后，只有在第一次打开时，才会自动发送请求获取基金信息。之后这个这个窗口不会被关闭（除非用户手动点击叉叉按钮），只会被隐藏。下次用户再点击AI助手图标时，就直接显示这个窗口。这样就可以保留用户在这个窗口里输入的问题和AI助手的回答，方便用户随时查看之前的对话记录。
* AI助手窗口支持历史上下文的功能。也就是说，用户在这个窗口里输入的问题，AI助手会将之前的对话记录作为上下文信息，一起发送给AI模型，这样AI模型就可以更好地理解用户的问题，并给出更准确的回答。当上下文信息过多时，可以只保留最近的对话记录，或者对对话记录进行摘要（可以通过AI进行摘要），提取出关键信息，作为上下文发送给AI模型。
* AI助手窗口有使用时效，当天内用户第一次打开这个窗口时，系统会记录一个时间戳。之后这个窗口的使用时效截止为第二天的0点。也就是说，用户在当天内多次打开这个窗口，都是在同一个使用时效内，不会重新发送请求获取基金信息。只有当第二天0点之后，用户再次打开这个窗口时，才会重新发送请求获取基金信息，并更新使用时效的截止时间。
* 如果用户手动关闭了这个窗口，下次用户再点击AI助手图标时，系统会认为这是第一次打开这个窗口，会重新发送请求获取基金信息，并更新使用时效的截止时间。
* AI助手窗口的信息只在内存中保存，不会被持久化到localStorage中。刷新页面后，窗口里的信息会被清空。用户再次打开这个窗口时，会重新发送请求获取基金信息，并更新使用时效的截止时间。
* 如果API调用失败，窗口里会显示错误信息，并提供一个重试按钮，用户点击后会重新发送请求获取基金信息。
* 窗口的右上角增加一个“常用问题”按钮，点击后会显示一个常用问题的列表，用户可以选择一个常用问题的名字，AI助手会根据这个名字，结合当前基金的信息，向AI模型发送请求，并将AI模型的回答显示在窗口里。此问题也会被记录到窗口的历史内容里，作为人工输入的快捷方式来处理。


#### 实现细节
##### 提示词模板
提示词模板放在一个配置文件中。方便将来的修改和扩展。模板中可以使用一些预定义好的变量：包括
  * code:基金代码
  * name:基金名称
  * history:用户的历史交易信息，包括用户买入卖出这个基金的时间，数量，价格等信息，可以是个JSON字符串。
  * fullCapacity:基金的满仓份额
  * initialCapacity:用户投资这个基金的初始份额
  * initialDate:用户投资这个基金的起始日期
  * initialPrice:用户投资这个基金的初始价格
  * currentPrice:当前这个基金的价格
  * currentDate:当前日期
  * previousPrice:前值
  * previousDate:前值日期
  * rate:当前价格和前值的涨跌幅
  * marketValue:当前这个基金的市场价值
  * position:当前这个基金的仓位
  * positionRate:当前这个基金的仓位占比
  * profit:当前这个基金的整体盈利
  * avgCostPrice：当前这个基金的平均成本价格

模板使用这些变量来构造提示词，向AI模型发送请求。比如：

```text
请你扮演一个投资顾问，给我分析一下这个基金（基金代码：{code}，基金名称：{name}）。
这是这个基金的基本信息：满仓份额是{fullCapacity}，我投资这个基金的初始份额是{initialCapacity}，起始日期是{initialDate}，初始价格是{initialPrice}。
当前这个基金的价格是{currentPrice}，当前日期是{currentDate}，前值是{previousPrice}，前值日期是{previousDate}，当前价格和前值的涨跌幅是{rate}。
当前这个基金的市场价值是{marketValue}，当前这个基金的仓位是{position}，当前这个基金的仓位占比是{positionRate}，当前这个基金的整体盈利是{profit}，当前这个基金的平均成本价格是{avgCostPrice}。
这是我投资这个基金的历史交易信息：{history}。
请你根据这些信息，结合当前的国内国外市场情况，政治经济情况，行业发展情况等，帮我分析一下这个基金的表现，未来的机会和风险。
```
##### 常用问题列表
常用问题列表也和提示词模板一样，放在同一个配置文件中（通过不同的类型来和初始提示词模板区分开），用户可以修改这个配置文件，增加或删除常用问题，或者修改常用问题的内容。常用问题的内容也可以使用一些预定义好的变量，和提示词模板一样。 示例： 
* 信息汇总
```text
请列出最新的和本基金相关的国内外信息，及其影响，以表格形式展示。
```
* 盈亏分析
```text
请分析一下这个基金的盈亏情况，主要是哪些因素导致的盈亏。
```
* 机会分析
```text
请分析一下这个基金未来的机会，主要是哪些因素导致的机会。
```
* 风险分析
```text
请分析一下这个基金未来的风险，主要是哪些因素导致的风险。
```
* 震荡分析
```text
请分析基金{code}是否适合震荡区间分析。如果不适合，请直接回复“{name}不适用于震荡区间分析”，不要有多余解释。如果适合，则形式显示各区间及其含义。然后基于目前该基金净值所处区间，给出推荐的投资策略。只显示这两部分内容，不要有其他任何多余的描述和陈述（包括“适合震荡区间分析”），不要做解释，不要用章节号。提供给你这个基金的当前价格：{currentPrice}，当前日期：{currentDate}，给你做参考。
```


##### 上下文压缩
当对话记录过多时，可以通过AI模型进行摘要，提取出关键信息，作为上下文发送给AI模型。在窗口的右下方，显示当前窗口的上下文信息长度。

用以下数据结构代表窗口内容（windowContext）：
* 历史内容（historyContent）：存放窗口的历史对话信息。
* 摘要内容（summaryContent）：存放对历史内容进行摘要后的关键信息。
* 新增内容（newContent）：摘要后新增的对话内容。

应用逻辑如下：
* 刚开始的时候，三个字段都为空，新的内容被添加到newContent里。
* 当newContent达到一定的长度（超过阈值，比如10K）时，就将newContent添加到historyContent中，清空newContent，并对合并后的historyContent进行摘要，存放到summaryContent中。
* 当需要获取窗口内的所有原始内容时，就返回historyContent和newContent的合并内容。主要用于AI助手窗口的恢复。
* 当需要获取窗口内当前上下文时，就返回summaryContent和newContent的合并内容。主要用于向AI模型发送请求时使用。

摘要可以通过给AI模型发送请求来实现。比如：
```text
请你帮我对以下内容进行摘要，提取出关键信息：
{content}
请你将摘要后的内容返回给我。
``` 
这个请求，不会被记录到窗口的历史内容里。
