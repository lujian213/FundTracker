# Smart Add or Update Fund Feature

在主界面上增加智能添加或更新基金的功能。通过上传截屏图片，系统可以自动识别出基金的相关信息（如基金代码、基金名称、当前价格、盈利等），并根据识别结果智能地添加新的基金或更新已有基金的信息。

## 界面入口
* 在主界面添加基金或指数的圆形按钮左边，显示一个新的圆形按钮，图标为相机或图片，用户点击后弹出文件选择窗口，允许用户上传多张基金信息的截屏图片。过滤条件为仅允许上传图片文件（如jpg、png等）。
* 用户选择图片，关闭文件选择窗口后，系统开始处理图片并识别其中的基金信息。

## 窗口设计及功能
### 进度窗口
* 处理过程中，显示一个加载动画或进度条，提示用户正在识别图片中的基金信息，要显示识别的进度。包括识别的总图片数量、已识别的图片数量、成功识别的基金数量、失败识别的图片数量等信息。
* 如果识别过程中发生错误（如图片格式不支持、图片内容无法识别等），在进度窗口中显示相应的错误信息，并继续处理剩余的图片。
* 识别完成后，自动关闭进度窗口，并弹出结果窗口显示识别结果。
### 识别结果窗口
* 识别完成后，弹出一个结果窗口，显示识别的结果。
* 结果窗口中，显示一个列表，每一行显示一个识别出的基金信息（如基金代码、基金名称、持有份额、基金净值、净值日期、累计盈利），以及将要进行的操作类型（添加或更新），新的仓位信息（满仓额度、初始持仓、起始日期，初始价格，其中每个字段都要显示之前的值和将要更新的值，更新的值用红色字体显示，之前的值用绿色字体显示，例如：123.45 -> 125.67。中间的箭头用图标表示。如果之前没有值，则显示为"-"。
* ）。最后有一列显示一个多选按钮。在表头提供全选和反选按钮，用户可以选择要添加或更新的基金信息。表格提供一个总计行，显示成功识别的基金数量和失败识别的图片数量。表格最多同时显示10行，超过10行时，使用滚动条显示。滚动条的滚动操作不影响表头和总计行的显示，且滚动条的出现不会遮挡表格内的内容。表格应该定高，不会因为行数的变化而改变表格的高度。
* 对于识别失败的图片，在结果窗口表格下方显示一个错误信息区域，以文本的形式显示识别或处理失败的图片名称（仅文件名，不需要路径），以及对应的错误信息（如无法识别出基金代码、持有份额等信息，或这计算初始份额有误等信息）。如果有多张图片识别失败，则显示多条错误信息，以换行分割。每条错误信息前面显示一个警告图标，以红色字体显示错误信息文本。
* 结果窗口底部显示一个"确认"按钮，用户点击后根据选择的基金信息进行添加或更新操作，操作完成后，关闭窗口。
* 结果窗口右上角有一个关闭按钮，用户点击后关闭窗口，不进行任何添加或更新操作。

### 图形识别细节
* 系统使用图像识别技术（如OCR）来识别图片中的文本信息。
* 需要识别出以下的信息：
  * 基金代码：code
  * 基金名称：name，仅作为显示使用，不作为识别的主要依据。
  * 持有份额：share
  * 基金净值：current_price
  * 净值日期：current_price_date，其中年份使用当前年份，月份和日期根据图片中的信息识别。
  * 累计盈利：profit
* 如果不能识别上述信息中的任意一项，则认为该图片识别失败。

### 计算逻辑
* 操作类型：对于识别成功的基金信息，系统首先根据基金代码检查是否已经存在于系统中。
  * 如果基金代码不存在，则为添加操作。
  * 如果基金代码已经存在，则为更新操作。
* 新的仓位信息：
  * 满仓额度：如果原来没有配置满仓额度，则新仓位信息的满仓额度为识别出来的持有份额（share）的两倍，取整到千（如持有份额为 1234.56，则满仓额度为 2000）；如果原来已经配置了满仓额度，则保持不变。
  * 初始持仓：如果原来没有配置满仓额度，则新仓位信息的初始持仓为识别出来的持有份额；如果原来已经配置了满仓额度，则需要进行计算调整。计算公式为：新的初始持仓 = 识别出来的持有份额（share）- 该基金在净值日期（current_price_date）之前的交易中买入的份额总和 + 该基金在净值日期（current_price_date）之前的交易中卖出的份额总和。这里的买入和卖出份额总和不包含净值日期当天的交易。如果计算出来的新的初始持仓小于0，则操作失败，在结果窗口的错误信息区域显示相应的错误信息（如"识别的持有份额与历史交易记录不一致，无法计算出合理的初始持仓，请手动调整后再进行识别添加或更新"）。如果计算出来的新的初始持仓大于等于0，则为正常。
  * 起始日期：如果原来已经配置了起始日期，则保持不变；如果原来没有配置起始日期但该基金有交易记录，则新仓位信息的起始日期为最早交易日期；如果原来没有配置起始日期且该基金没有交易记录，则新仓位信息的起始日期为识别出来的净值日期（current_price_date）。
  * 初始价格：如果原来没有配置初始价格，则新仓位信息的初始价格为根据识别出的基金净值（current_price）；如果原来已经配置了初始价格，则需要进行计算调整。计算公式与初始价格调整功能中（@features/feature-inital-price-adjustment.md）描述的计算公式相同，使用识别出的持有份额、当前价格、累计盈利等信息进行计算：
    * 初始价格 = ((当前份额 × 当前价格) + 卖出总额 - 买入总额 - 参考盈利) / 初始份额
    * 当前份额 = 识别出来的持有份额（share）
    * 当前价格 = 识别出来的基金净值（current_price）
    * 参考盈利 = 识别出来的累计盈利（profit）
    * 初始份额 = 新的初始持仓（根据上述计算得出）
    * 卖出总额和买入总额不包含今日的交易。

### 添加或更新操作
* 当用户点击结果窗口中的"确认"按钮后，系统根据用户选择的基金信息进行添加或更新操作。
* 对于添加操作，系统将识别出来的基金信息添加到系统中，并且将新的仓位信息（满仓额度、初始持仓、起始日期、初始价格）保存到对应基金的数据中。
* 对于更新操作，系统将识别出来的基金信息与系统中已有的基金信息进行比较，更新系统中对应基金的数据，并且将新的仓位信息（满仓额度、初始持仓、起始日期、初始价格）保存到对应基金的数据中。
