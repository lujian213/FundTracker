# Valuation Data Enhancement

## 估值与前值数据准确性增强

### 问题描述
目前的估值数据和前值数据在某些情况下存在不准确的问题，主要原因是数据来源不稳定以及计算逻辑存在缺陷。这导致用户在查看基金的估值和前值时可能会看到错误的信息，影响用户的投资决策。

### 增强要点
* 比较估值日期（valuationDate）和历史净值的最近一条净值的日期，如果估值日期早于最近一条净值的日期，则使用最近一条净值的数据作为估值数据，对应净值日期作为估值日期。
这种情况下，前值数据也需要进行相应的调整，前值应该是历史净值的最近一条净值的前一条数据，前值日期应该是历史净值的最近一条净值的前一条数据的日期。
* 比较估值日期（valuationDate）和前值日期（netWorthDate），如果估值日期不晚于前值日期，则前值数据需要进行调整，前值应该是历史净值中，最接近估值日期（小于）的那条净值记录的值，前值日期也是该净值记录所以对应的日期。

### 实施方案
因为系统里面有很多地方直接使用了估值数据和前值数据，所以需要在数据层进行增强，确保所有使用到估值数据和前值数据的地方都能得到准确的数据。具体实施方案如下：
1. 在数据层增加一个函数，用于获取准确的估值数据和前值数据。这个函数会根据上述增强要点的逻辑，查询历史净值数据，并进行相应的调整，返回准确的估值数据和前值数据。
2. 找出系统中所有使用估值数据和前值数据的地方，将这些地方的代码修改为调用上述函数，确保所有使用到估值数据和前值数据的地方都能得到准确的数据。
3. 进行全面的测试，确保增强后的数据准确性，并且没有引入新的问题。

### 具体实施注意事项
目标是把增强逻辑限定在getValuation函数的范围之内，不把改动扩散。其他地方要改的就是修改调用方式（从直接引用ValuationData中的字段，改成调用getValuation）。为了不遗漏修改点。可不
可以采取下面的步骤：
1. 先实现getValuation函数。该函数返回ValuationData对象，包含了修正过的估值数据和前值数据。这个函数内部实现上述增强逻辑，确保返回的数据是准确的。
2. 将ValuationData中的相关字段（估值，前值，估值日期，前值日期等）改名，然后build，从出错列表里面找到所有的直接引用了相关字段的地方。分析那些引用的地方是需要修改的（理论上都应该修改。保险起见，可以列出来review和confirm）。
3. 将需要修改的地方都换成getValuation函数的调用（具体可能是getValuation().valuation，getValuation().netWorthDate等）。唯一的例外是getValuation函数内部的实现逻辑，还是保持直接引用字段的方式。
4. 确保build成功，没有遗漏任何需要修改的地方。
5. 将之前修改的字段名改回原来的名字（如果需要的话）。getValuation函数内部也要相应修改字段名，保持一致。
5. 修改完成后，进行全面的测试，确保所有使用到估值数据和前值数据的地方都能得到准确的数据，并且没有引入新的问题。
