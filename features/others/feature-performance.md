# Performance Feature

我想要构建一个内存数据缓存层，用来提高当前系统的性能。基本想法是通过数据缓冲层将数据获取与界面展示分离。
* 内存缓存数据包括基金历史净值，实时估值和市场热点。交易信息和基金基本信息不需要特意缓存，因为它们的更新频率较低。直接用现有方案即可。
* 页面初始话loading时，先检查是否有缓存数据存在，如有则直接使用缓存数据进行展示，如没有则先获取数据。
* 所有界面操作都是利用缓存的数据直接进行计算和展示，避免每次操作都需要重新获取数据。
* 缓存数据的更新通过定时刷新和手动刷新两种方式进行。刷新操作在后台进行，不会阻塞界面操作。刷新的数据以单个基金为单位，不会出现单个基金内的数据不一致的情况。单个基金的数据刷新完成后，会立即更新
主界面上的对应基金的信息。
  * 手动刷新即通过目前在界面右上方的刷新按钮来触发数据更新。刷新操作会重新获取所有需要缓存的数据，并更新内存缓存。
  * 定时刷新即每隔一定时间自动触发。基金历史净值数据可以每20分钟刷新一次。实时估值信息和市场热点可以每3分钟刷新一次。定时刷新操作会重新获取所有需要缓存的数据，并更新内存缓存。
* 为了提高性能，可以采用多线程方式，利用多个线程，每个线程负责多个基金的方式进行。选取合适的线程池大小，既能提高性能又不会过度占用系统资源。每个线程负责获取和更新多个基金的数据，确保数据刷新效率。
* 在数据刷新过程中，界面上可以显示一个小的加载动画和信息显示，提示用户数据正在刷新。目前已有这个功能，请沿用。

## 目标：
* 性能改进后，界面显示的数据与当前（为改进前）完全一致，且数据的准确性和一致性得到保证。
* 所有界面操作对应的数据显示做到秒开，不需要任何的网络数据获取（除了第一次打开网页，没有任何数据缓存的情况下）。
* 数据刷新操作在后台进行，不会阻塞界面操作。刷新完成后，主界面上的对应基金的信息能够立即更新。
* 定时刷新和手动刷新都能够正确地更新内存缓存，并且界面上的数据能够正确地反映最新的缓存数据。
* 通过多线程方式提高数据刷新效率，确保在合理的时间内完成数据更新，同时不会过度占用系统资源。
* 在数据刷新过程中，界面上能够正确地显示加载动画和信息提示，告知用户数据正在刷新。
* 确保数据刷新过程中不会出现单个基金内的数据不一致的情况，即每个基金的数据刷新完成后，主界面上的对应基金的信息能够立即更新。
* 确保在数据刷新过程中，界面上的其他操作能够正常进行，不会因为数据刷新而出现卡顿或响应迟钝的情况。
