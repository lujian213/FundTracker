# Virtual Trade Feature
## 虚拟交易

虚拟交易功能利用定义好的交易策略，模拟用户在真实市场中的交易行为。用户可以通过虚拟交易功能测试和优化他们的交易策略，而不需要冒实际资金的风险。

## 前提与假设
* 虚拟交易每天只进行0到1笔交易。
* 交易策略的算法和逻辑由系统预先配置好，用户无法修改。
* 策略参数支持在系统配置中修改（后续可扩展到用户界面）。

## 界面入口
在基金的详情页上增加一个"虚拟交易"按钮，用户点击后进入虚拟交易界面。

## 虚拟交易界面

### 输入字段

界面内要求用户输入以下信息：

* **现有现金**：用户当前持有的现金金额。
  * 默认值=（基金的满仓份额-基金的现有份额）*开始日期的基金净值。如果结果为负数，则设为0。
  * 如果基金没有满仓份额的配置，则默认为10万。
  * 如果用户修改了开始日期，则现有现金的默认值也会随之更新（根据新的开始日期计算）。
  * 数值以千分位分隔符显示，输入时允许输入千分位分隔符，系统会自动去除分隔符进行计算。保留两位小数。必须大于等于0。

* **现有份额**：用户当前持有的基金份额数量。
  * 默认取值为对应基金在开始日期（下一个输入）的真实份额数量。即用户选择的开始日期对应基金的净值记录中的份额数量。
  * 如果该日期没有对应的基金份额或为0，则设为10万除以该日期的基金净值。
  * 该字段的取值与用户选择的开始日期相关联，用户修改开始日期时，该字段的默认值也会随之更新。
  * 数值以千分位分隔符显示，保留两位小数。必须大于等于0。

* **开始日期**：用户选择使用交易策略开始虚拟交易的日期。
  * 默认值为该基金的建仓日期（初始仓位的起始日期）。
  * 如果该基金没有建仓日期（没有配置初始仓位），则默认值为90天前。
  * 该值必须选择一个历史日期，且不能早于基金历史净值的最早日期。

### 辅助信息

* 在现有份额下面显示一行红色小字，给出现有份额对应的当时市场价值：
  ```text
  当时市场价值 = 现有份额 * 开始日期的基金净值
  ```

* 如果用户选择的开始时间在基金的建仓日期之后或等于基金的建仓时间，则意味着存在实盘交易。在开始日期控件下方用蓝色小字显示实盘盈亏金额（从用户选择的开始时间到今天的基金持仓盈亏）。否则，不显示实盘盈亏信息。盈亏金额为正数时显示为红色，负数时显示为绿色。

### 交互操作

* 日期选择框右侧有一个重置按钮，点击后重置所有输入字段为默认值。
* 界面上有一个开始按钮，点击后开始虚拟交易计算。

### 策略Tab组件

下方有一个tab组件，组件内的tab个数和系统预先配置好的交易策略个数相同：
* tab的标题为交易策略的名称，标题上显示hovertip（策略原理）。
* 点击不同的tab可以查看不同交易策略的历史虚拟交易内容，以及当天交易的提示信息。
* 执行虚拟交易后，在具有最高策略总盈亏的tab上，在策略名称后面加上大拇指图标，并默认切换到该tab。
  * 如果有并列第一名，则把图标加到tab次序靠前的策略上。
  * 如果多个策略的策略总盈亏都为0且都没有做任何交易，则都不加图标。

## 历史虚拟交易表格

自用户选择的开始日期到当前日期的虚拟交易结果表格：

| 列名 | 说明 |
|------|------|
| 交易日期 | 虚拟交易的日期（yyyy-MM-dd格式），自开始日期到当前日期的前一天 |
| 交易方向 | 买入/卖出/不操作 |
| 基金净值 | 该日的基金净值（保留4位小数） |
| 交易数量 | 买入或卖出的基金份额数量（不操作时为0） |
| 交易金额 | 交易数量 * 当日基金净值 |
| 交易后现金 | 进行交易后的现金金额 |
| 交易后份额 | 进行交易后的基金份额数量 |
| 交易后总资产 | 交易后现金 + 交易后份额 * 后一日基金净值（最后一条记录用当日净值或估值） |
| 较前一日盈亏金额 | 交易后总资产 - 前一日总资产（首条记录用初始总资产） |
| 交易后盈亏金额 | 交易后总资产 - 初始总资产 |

**表格规范**：
* 滚动条显示，一屏最多10条记录，默认滚动到最下面显示最新记录。
* 所有数字精确到小数点后2位，以千分位表示。
* 盈亏金额为正数时显示为红色，负数时显示为绿色。
* 交易方向字段上有tooltip，显示策略决策的理由（如"金叉"、"超卖"等）。

**初始总资产计算**：
```text
初始总资产 = 现有现金 + 现有份额 * 开始日期的基金净值
```

## 策略总盈亏

在表格上方显示该策略从开始日期到当前日期的总盈亏：
* **总盈亏金额**：最后一条记录的交易后总资产 - 初始总资产
* **盈利率**：总盈亏金额 / 初始总资产（百分比形式）

## 今日交易提示

显示推荐的今日交易操作（买入/卖出/不操作）和交易数量。

## 策略系统设计

### 策略接口定义

```typescript
interface VirtualStrategy {
  name: string;              // 策略名称
  description: string;       // 策略原理（用于UI tooltip）
  decide(ctx: VirtualStrategyContext): VirtualTradeDecision;
}

interface VirtualTradeDecision {
  action: 'buy' | 'sell' | 'hold';
  shares: number;
  reason?: StrategyReason;   // 决策理由（用于UI tooltip）
}
```

### 策略上下文

```typescript
interface VirtualStrategyContext {
  history: HistoricalPoint[];           // 截至前一日的历史净值
  cash: number;                         // 当前现金
  shares: number;                       // 当前份额
  startNav: number;                     // 起始净值
  transactionHistory: Transaction[];    // 过往交易记录（用于连续策略）
  fundConfig?: FundConfig;              // 基金配置（仓位限制等）
  userConfig?: UserConfig;              // 用户配置（风险偏好等）
}
```

### 参数配置系统

策略参数采用统一的 `StrategyParam` 结构，支持动态表达式计算：

```typescript
interface StrategyParam {
  value: string | number | boolean;     // 参数值（支持表达式）
  type: "string" | "number" | "bool";    // 目标类型
  description: string;                   // 参数描述（用于UI显示）
}
```

**表达式格式**：`${expr}`
* 使用 `expr-eval` 库解析计算
* 可引用上下文变量：`cash`, `shares`, `startNav`, `fundConfig`, `userConfig`
* 示例：`${(cash+shares*startNav)/startNav/10}` 表示基础交易单位为初始总资产的十分之一

### 策略注册表

系统采用注册表模式管理策略，配置与实现分离：
* `strategyConfig.ts`：策略元信息（名称、描述、参数模板）
* `strategyRegistry.ts`：策略动态加载映射
* `virtualTradeStrategies/*.ts`：独立策略实现文件

## 现有策略列表

| 策略名称 | 策略原理 |
|----------|----------|
| 趋势追踪策略（移动平均线金叉死叉） | 通过短期均线与长期均线的交叉识别趋势启动与反转 |
| 均值回归策略（布林带反转） | 当价格偏离均值过大时倾向于回归，布林带衡量偏离程度 |
| 恒定混合策略（股债平衡） | 保持基金仓位占总资产固定比例，通过再平衡实现高抛低吸 |
| 固定金额正金字塔策略 | 价格下跌时固定金额买入更多份额，价格上涨时固定金额卖出 |
| 估值分位数策略 | 基于历史净值分位数判断估值高低，低分位数买入高分位数卖出 |
| 回撤买入策略 | 在净值从高点回撤超过阈值时逐步买入 |

---

## 实现注意事项

* 虚拟交易从用户输入的开始日期进行计算，直到当前日期的前一天。
* 性能优化：复用前一天的计算结果，避免重复计算。
* 交易策略的名称、描述、参数模板放在配置文件中，方便后续修改和扩展新策略。
