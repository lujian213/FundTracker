# Virtual Trade Feature
## 虚拟交易
虚拟交易功能利用定义好的交易策略，模拟用户在真实市场中的交易行为。用户可以通过虚拟交易功能测试和优化他们的交易策略，而不需要冒实际资金的风险。

## 前提与假设
* 虚拟交易每天只进行0到1比交易。
* 交易策略的算法和逻辑由系统预先配置好，用户无法修改。


## 界面入口
在基金的详情页上增加一个“虚拟交易”按钮，用户点击后进入虚拟交易界面。

## 虚拟交易界面
界面内要求用户输入以下信息：
* 现有现金：用户当前持有的现金金额。
  * 默认值=（基金的满仓份额-基金的现有份额）*开始日期的基金净值。如果结果为负数，则设为0。
  * 如果基金没有满仓份额的配置，则默认为10万。
  * 如果用户修改了开始日期，则现有现金的默认值也会随之更新（根据新的开始日期计算）。
  * 数值以千分位分隔符显示，输入时允许输入千分位分隔符，系统会自动去除分隔符进行计算。保留两位小数。必须大于等于0。
* 现有份额：用户当前持有的基金份额数量。
  * 默认取值为对应基金在开始日期（下一个输入）的真实份额数量。即用户选择的开始日期对应基金的净值记录中的份额数量。相关的份额计算，应该和其他功能中的某日基金份额的计算方式保持一致，且使用同一套计算逻辑和代码以保证一致性。
  * 如过该日期没有对应的基金份额或为0，则设为10万除以该日期的基金净值。
  * 该字段的取值与用户选择的开始日期相关联，用户修改开始日期时，该字段的默认值也会随之更新（规则如上所述）。用户也可以手动修改该字段的值，覆盖默认值。
  * 数值以千分位分隔符显示，输入时允许输入千分位分隔符，系统会自动去除分隔符进行计算。保留两位小数。必须大于等于0。
* 开始日期：用户选择使用交易策略开始虚拟交易的日期。
  * 默认值为该基金的建仓日期（初始仓位的起始日期）。
  * 如果该基金没有建仓日期（没有配置初始仓位），则默认值为90天前。
  * 该值必须选择一个历史日期，且不能早于基金历史净值的最早日期。
* 在现有份额下面显示一行红色小字，给出现有份额对应的当时市场价值，形式为“当时市场价值：123.45”，其中数值为计算出来的金额，保留小数点后两位，以千分位分隔符显示。
计算公式为：
```text
当时市场价值 = 现有份额 * 开始日期的基金净值
```
这个信息可以帮助用户更好地理解现有份额的价值。
* 如果用户选择的开始时间在基金的建仓日期之后或等于基金的建仓时间，则意味着存在实盘交易。在开始日期控件下方用蓝色小字显示实盘盈亏金额（从用户选择的开始时间到今天的基金持仓赢亏）。实盘盈亏的算法参照已经实现的基金持仓盈亏功能（请使用相同的算法和代码）。
否则，不显示实盘盈亏信息。显示形式为“实盘盈亏：1234.45”，其中数值为计算出来的金额，保留小数点后两位，以千分位分隔符显示。盈亏金额为正数时显示为红色，负数时显示为绿色。
* 日期选择框右侧有一个重置按钮，点击后，会重置开始日期为默认值，并且重置现有份额为默认值（根据新的开始日期计算的默认份额）。同时，重置现有现金为默认值10万。
* 界面上有一个开始按钮，点击后开始虚拟交易。
下方有一个tab组件。组件内的tab个数和系统预先配置好的交易策略个数相同。每个tab对应一个交易策略，
* tab的标题为交易策略的名称。
* tab的标题上显示hovertip，内容是该交易策略的策略原理。
* 点击不同的tab可以查看不同交易策略的历史虚拟交易内容，以及当天交易的提示信息（如当天是否有交易，交易方向和数量）。
* 在虚拟交易页面上，当执行了虚拟交易之后，在具有最高的策略总盈亏的交易策略所在的tab上，在交易策略名字后面加上一个大拇指的图标。并默认切换到该tab上。
  * 在用户重新点击开始按钮，执行新的计算时，原有大拇指图标应该被消除，再根据新的计算结果，在相应的tab上加上图标。并默认切换到该tab上。
  * 如果有并列第一名，则把图标加到tab次序靠前的策略上。
  * 如果多个策略的的策略总盈亏都为0，并且都没有做任何的买入或卖出，则都不加图标。

### 历史虚拟交易
自用户选择的开始日期到当前日期的虚拟交易结果表格，包括以下内容：
* 交易日期：虚拟交易的日期，自开始日期到当前日期的前一天（若该日没有历史净值，则跳过）。yyyy-MM-dd格式
* 交易方向：买入/卖出/不操作
* 基金净值：该日的基金净值（保留4位小数）
* 交易数量：买入或卖出的基金份额数量。不操作时为0
* 交易金额：买入或卖出的金额。不操作时为0. 计算公式为：交易数量 * 当日基金净值
* 交易后现金：进行交易后的现金金额
* 交易后份额：进行交易后的基金份额数量
* 交易后总资产：进行交易后的总资产金额，计算公式为：交易后现金 + 交易后份额 * 后一日基金净值（如果已经是最后一条净值记录，且今天存在估值，则用今天的估值计算；如果没有估值，则用最后一条净值记录计算）
* 较前一日盈亏金额：与前一日相比的盈亏金额，计算公式为：交易后总资产 - 前一日总资产（若是第一条记录，则前一日总资产为初始总资产）
* 交易后盈亏金额：进行交易后的盈亏金额，计算公式为：交易后总资产 - 初始总资产

- 所有数字如无特殊要求，一律精确到小数点后2位。盈亏金额为正数时显示为红色，负数时显示为绿色。以千分位表示。
---
**初始总资产=现有现金 + 现有份额 * 开始日期的基金净值**

### 策略总盈亏
* 在表格上方显示该策略从开始日期到当前日期的总盈亏金额，计算公式为：最后一条记录的交易后总资产 - 初始总资产。
* 后面加上盈利率信息，计算公式为：总盈亏金额 / 初始总资产。盈亏率为百分比形式。
* 以上数字，如无特殊要求，一律精确到小数点后2位。盈亏金额为正数时显示为红色，负数时显示为绿色。以千分位分隔符显示。

### 今日交易提示
显示推荐的今日交易操作（买入/卖出/不操作）和交易数量。

## 虚拟交易策略
定义出虚拟交易策略的接口。这样可以方便地添加新的交易策略，或者修改现有的交易策略，而不需要修改虚拟交易功能的其他部分。
* 交易策略的输入是截止到x-1日基金每日净值（净值开始日期由具体交易策略自行选择，从完整历史基金净值中挑选），截止到x-1日的现金值和份额值
* 交易策略的输出是x日的交易操作（买入/卖出/不操作）和交易数量。
* 交易策略的每一天的计算结果都要有解释，说明为什么会有这样的交易操作或为什么没有操作。具体由交易策略自定。这个信息会在虚拟交易界面上以hovertip展示，帮助用户理解交易策略的逻辑和行为。
* 每个交易策略都要有一个策略原理的说明，说明该策略的基本逻辑和理论依据。这个信息会在虚拟交易界面上以hovertip展示，帮助用户理解交易策略的基本思路。

目前有的虚拟交易策略：
### 趋势追踪策略（移动平均线金叉死叉）
#### 策略原理
基于技术分析中的趋势跟随理论，认为价格趋势一旦形成将持续一段时间。通过短期均线与长期均线的交叉来识别趋势的启动与反转，在上升趋势中买入持有，在下降趋势中卖出离场。
策略特点:

|维度| 	描述                    |
|---|------------------------|
|✅ 优点	| 能捕捉主要趋势，在单边牛市中表现优异     |
|❌ 缺点	| 震荡市场容易反复被"打脸"，产生频繁亏损交易 |
|📊 适用市场	| 单边牛市或单边熊市              |
|⚠️ 风险等级	| 高                      |
|🔄 交易频率	| 中等                     |

#### 输入参数
| 参数名 | 说明 | 推荐值             |
|--------|------|-----------------|
| `short_window` | 短期均线窗口 | 5天              |
| `long_window` | 长期均线窗口 | 20天             |
| `base_unit` | 基础交易单位 | 初始总资产/开始日期净值/10 |

#### 计算规则
1. 计算过去 `short_window` 日的净值简单移动平均线 `MA_short`
```text 
MA_short = sum(净值[-short_window:]) / short_window
```

2. 计算过去 `long_window` 日的净值简单移动平均线 `MA_long`
```text 
MA_long = sum(净值[-long_window:]) / long_window
```
3. 比较今日与昨日的均线关系，判断是否发生交叉

## 交易信号生成
```python
# 获取今日和昨日的均线值
MA_short_today = 计算MA_short(今日)
MA_short_yesterday = 计算MA_short(昨日)
MA_long_today = 计算MA_long(今日)
MA_long_yesterday = 计算MA_long(昨日)

# 判断金叉（买入信号）
if MA_short_today > MA_long_today and MA_short_yesterday <= MA_long_yesterday:
 信号 = "买入"
# 判断死叉（卖出信号）
elif MA_short_today < MA_long_today and MA_short_yesterday >= MA_long_yesterday:
 信号 = "卖出"
else:
 信号 = "不动"
```
#### 交易份额计算
```python
当前净值 = 净值数组[-1]  # 今日净值

if 信号 == "买入":
    # 使用50%现金买入，同时不超过base_unit的约束
    最大可买份额 = 剩余现金 / 当前净值
    目标买入份额 = min(剩余现金 * 0.5 / 当前净值, base_unit)
    实际买入份额 = min(目标买入份额, 最大可买份额)
    
    输出 = ("买入", 实际买入份额)
    
elif 信号 == "卖出":
    # 卖出50%持仓，同时不超过base_unit的约束
    目标卖出份额 = min(当前份额 * 0.5, base_unit)
    实际卖出份额 = min(目标卖出份额, 当前份额)
    
    输出 = ("卖出", 实际卖出份额)
    
else:  # 信号 == "不动"
    输出 = ("不动", 0)
```
### 均值回归策略（布林带反转）

#### 策略原理
基于统计回归理论，认为价格短期内会围绕均值波动。当价格偏离均值过大时，倾向于回归。布林带提供了衡量偏离程度的量化指标：价格触及上轨视为超买（卖出信号），触及下轨视为超卖（买入信号）。

策略特点：

| 维度 |	描述 |
|---|--|
|✅ 优点|	震荡市表现稳健，实现低买高卖|
|❌ 缺点|	强单边趋势中容易"逆势死扛"，造成较大亏损|
|📊 适用市场|震荡市、区间整理行情|
|⚠️ 风险等级|	中等|
|🔄 交易频率	|中高|

#### 输入参数
| 参数名 | 说明 | 推荐值 |
|--------|------|--------|
| `bb_window` | 布林带计算窗口 | 20天 |
| `num_std` | 标准差倍数 | 2倍 |
| `base_unit` | 基础交易单位 | 初始总资产/开始日期净值/10  |

#### 计算规则
1. 计算过去 `bb_window` 日净值的中轨（简单移动平均）`middle_band`
```text
middle_band = sum(净值[-bb_window:]) / bb_window
```
2. 计算过去 `bb_window` 日净值的标准差 `std`
```text
std = 标准差(净值[-bb_window:])
```
3. 计算上下轨
```text
upper_band = middle_band + num_std * std
lower_band = middle_band - num_std * std
```

#### 交易信号生成
```python
当前净值 = 净值数组[-1]  # 今日净值

# 超卖区域（低于下轨）- 买入信号
if 当前净值 < lower_band:
 信号 = "买入"
# 超买区域（高于上轨）- 卖出信号
elif 当前净值 > upper_band:
 信号 = "卖出"
else:
 信号 = "不动"
```
#### 交易份额计算
```python
if 信号 == "买入":
    # 逆势交易，使用30%现金保守买入
    最大可买份额 = 剩余现金 / 当前净值
    目标买入份额 = min(剩余现金 * 0.3 / 当前净值, base_unit)
    实际买入份额 = min(目标买入份额, 最大可买份额)
    
    输出 = ("买入", 实际买入份额)
    
elif 信号 == "卖出":
    # 逆势卖出30%持仓
    目标卖出份额 = min(当前份额 * 0.3, base_unit)
    实际卖出份额 = min(目标卖出份额, 当前份额)
    
    输出 = ("卖出", 实际卖出份额)
    
else:  # 信号 == "不动"
    输出 = ("不动", 0)
```

### 恒定混合策略（股债平衡）

#### 策略原理
源自经典资产配置理论，保持基金仓位占总资产（市值+现金）的固定比例。通过定期再平衡实现机械的\"高抛低吸\"：当基金上涨导致仓位过高时卖出部分份额，当基金下跌导致仓位过低时买入部分份额。

策略特点：

|维度|	描述|
|---|------------------------|
|✅ 优点|	风险可控，强制止盈止损，符合长期投资理念|
|❌ 缺点	|牛市中收益会落后于满仓策略，需要定期触发交易|
|📊 适用市场	|所有市场类型，尤其适合波动市场|
|⚠️ 风险等级	|低|
|🔄 交易频率	|低（仅当偏离超过阈值时触发）|

#### 输入参数
| 参数名 | 说明 | 推荐值 |
|--------|------|--------|
| `target_ratio` | 目标仓位比例 | 50% |
| `rebalance_threshold` | 再平衡触发阈值 | 5% |
| `min_unit` | 最小交易单位 | 初始总资产/开始日期净值/10 |

#### 计算规则
1. 计算当前总资产
```text
   当前净值 = 净值数组[-1] # 今日净值
   持仓市值 = 当前份额 * 当前净值
   总资产 = 持仓市值 + 剩余现金
```
2. 计算当前仓位比例
```text
当前仓位比例 = 持仓市值 / 总资产
```

3. 计算目标持仓份额
```text
目标持仓市值 = 总资产 * target_ratio
目标持仓份额 = 目标持仓市值 / 当前净值
```

#### 交易信号生成
```python
偏离度 = abs(当前仓位比例 - target_ratio)

if 偏离度 > rebalance_threshold:
 if 当前仓位比例 > target_ratio:  # 仓位过高，需要卖出
     信号 = "卖出"
 else:  # 仓位过低，需要买入
     信号 = "买入"
else:
 信号 = "不动"
```
#### 交易份额计算
```python
if 信号 == "买入":
    # 计算需要买入的份额
    理论买入份额 = target_持仓份额 - 当前份额
    最大可买份额 = 剩余现金 / 当前净值
    实际买入份额 = min(理论买入份额, 最大可买份额)
    
    # 向下取整到最小交易单位
    实际买入份额 = (实际买入份额 // min_unit) * min_unit
    输出 = ("买入", 实际买入份额)
    
elif 信号 == "卖出":
    # 计算需要卖出的份额
    理论卖出份额 = 当前份额 - target_持仓份额
    实际卖出份额 = min(理论卖出份额, 当前份额)
    
    # 向下取整到最小交易单位
    实际卖出份额 = (实际卖出份额 // min_unit) * min_unit
    输出 = ("卖出", 实际卖出份额)
    
else:  # 信号 == "不动"
    输出 = ("不动", 0)
```

### 金额固定正金字塔买入/卖出策略

#### 策略原理
金额固定正金字塔策略是一种资金管理方法，核心思想是：**在价格下跌时分批买入，每次买入固定金额（而非固定份额），从而在低价位积累更多份额；在价格上涨时分批卖出，每次卖出固定金额，从而在高位锁定利润**。由于每次投入的金额固定，当价格越低时，买入的份额越多，实现了“越跌越买”且加仓量随价格降低而自动增大的效果；卖出时，价格越高，卖出的份额越少，保留了部分仓位继续享受上涨。
这种策略在震荡市或温和下跌行情中能有效降低平均成本，并在反弹时较快盈利。但在单边下跌行情中，可能会持续消耗现金；在单边上涨行情中，可能过早卖光仓位。

策略特点：

|维度|	描述|
|---|------------------------|
|✅ 优点	|自动实现低位多买、高位少买/少卖；执行简单，无需预测顶底；在震荡市中能有效降低平均成本。|
|❌ 缺点	|单边下跌中现金消耗快，可能过早耗尽资金；单边上涨中可能过早卖完仓位，错失后续涨幅。|
|📊 适用市场	|震荡市、箱体震荡、长期盘整且波动适中的市场。|
|⚠️ 风险等级	|中（需设置仓位上限和止损线）|
|🔄 交易频率	|取决于价格波动间隔，可能中等。|

#### 输入参数

| 参数名 | 说明 | 推荐值 |
|--------|------|--------|
| `initial_nav` | 初始参考净值（用于设定第一次触发价） | 当前净值 |
| `down_step` | 下跌触发间隔（百分比） | 5% |
| `up_step` | 上涨触发间隔（百分比） | 5% |
| `fixed_buy_amount` | 每次买入的固定金额（元） | 1000元 |
| `fixed_sell_amount` | 每次卖出的固定金额（元） | 1000元 |
| `max_position` | 最大允许持仓份额（防止无限加仓） | 10000份 |
| `min_cash_reserve` | 最低保留现金（元） | 100元 |

#### 计算规则
1. 记录上一次买入触发时的净值 `last_buy_nav`（初始可设为 `initial_nav * (1 - down_step)`，避免立即触发）  
   记录上一次卖出触发时的净值 `last_sell_nav`（初始可设为 `initial_nav * (1 + up_step)`）
2. 每日比较当前净值 `current_nav` 与参考净值，判断是否触发交易。

#### 交易信号生成
```python
# 初始化（策略开始运行时）
last_buy_nav = initial_nav * (1 - down_step)
last_sell_nav = initial_nav * (1 + up_step)

# 每日判断
触发买入 = False
触发卖出 = False

if current_nav <= last_buy_nav * (1 - down_step):
    触发买入 = True
    new_buy_ref = current_nav   # 更新参考价

if current_nav >= last_sell_nav * (1 + up_step):
    触发卖出 = True
    new_sell_ref = current_nav

# 冲突处理（极少同时发生，若发生可优先买入或根据仓位决定）
if 触发买入 and 触发卖出:
    # 简单处理：若当前仓位低于50%则买入，否则卖出（此处选择买入优先）
    触发卖出 = False
```
#### 交易份额计算
每次买入/卖出的金额固定，份额根据当前净值计算：

```python
if 触发买入:
    # 计算可买入的最大份额（考虑现金余额和仓位上限）
    max_buy_shares_by_cash = (剩余现金 - min_cash_reserve) // current_nav
    target_shares = fixed_buy_amount // current_nav   # 固定金额对应的份额（取整）
    buy_shares = min(target_shares, max_buy_shares_by_cash, max_position - 当前份额)
    if buy_shares > 0:
        last_buy_nav = new_buy_ref   # 更新参考净值
        输出 = ("买入", buy_shares)
    else:
        输出 = ("不动", 0)

elif 触发卖出:
    # 计算可卖出的份额
    target_shares = fixed_sell_amount // current_nav
    sell_shares = min(target_shares, 当前份额)
    if sell_shares > 0:
        last_sell_nav = new_sell_ref
        输出 = ("卖出", sell_shares)
    else:
        输出 = ("不动", 0)

else:
    输出 = ("不动", 0)
```
#### 状态更新
更新参考净值后，下一次触发将基于新的 last_buy_nav 或 last_sell_nav。



## 实现注意事项
* 在进行虚拟交易计算是，因为要对从开始日期到当前日期的每一天进行计算，所以需要考虑性能优化，尽可能用到前一天的计算结果。
* 虚拟交易从用户输入的开始日期进行计算，直到当前日期的前一天。前一天计算出来的交易方向和份额，都要转换为后一天的现金和份额的变化。
  * 买入：现金减少（减去交易金额），份额增加（增加交易份额），交易金额=该日净值*交易份额，
  * 卖出：现金增加（加上交易金额），份额减少（减少交易份额），交易金额=该日净值*交易份额，
  * 不操作：现金不变，份额不变
* 将交易策略的名称、策略原理放在一个配置文件中，方便后续对交易策略名称和策略原理的修改，如有新的交易策略的添加，也可以直接在配置文件中添加。
