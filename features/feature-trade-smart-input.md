# 交易记录智能录入功能

提供一个交易批量智能录入界面，用户可以在该界面中一次性导入多个交易记录的截屏文件，系统会自动识别并解析这些截屏文件中的交易记录信息，并将这些交易记录保存到系统中对应的基金的交易记录里。

### 界面入口

* 在基金交易明细窗口内，表格的右上方，与日期选择平齐处，在"批量输入"和“组合交易”按钮的中间，增加“智能输入”按钮，用户点击后弹出文件选择窗口，允许用户上传多张基金交易的截屏图片。过滤条件为仅允许上传图片文件（如jpg、png等）。
* 用户选择图片，关闭文件选择窗口后，系统开始处理图片并识别其中的基金交易信息。

## 窗口设计及功能
### 进度窗口
* 处理过程中，显示一个加载动画或进度条，提示用户正在识别图片中的基金信息，要显示识别的进度。包括识别的总图片数量、已识别的图片数量、成功识别的基金数量、失败识别的图片数量等信息。
* 如果识别过程中发生错误（如图片格式不支持、图片内容无法识别等），在进度窗口中显示相应的错误信息，并继续处理剩余的图片。
* 识别完成后，自动关闭进度窗口，并弹出结果窗口显示识别结果。
* 可以参照智能添加或更新基金功能中的进度窗口设计。

### 识别结果窗口
* 识别完成后，弹出一个结果窗口，显示识别的结果。样式和智能添加或更新基金功能中的结果窗口类似，但内容和交互逻辑有所不同。
* 结果窗口中，显示一个列表，
* 列表按照交易的日期进行分组，每个分组显示该日期的交易记录。每条交易记录显示以下信息：
   * 基金代码：code，这个信息在交易图片中是不存在的，需要根据基金名称在系统现有基金中匹配。匹配不上的话，显示红色的“<无法匹配>”，并且设置该记录无效，出错信息是"%name%无法根据基金名称匹配出系统中已有的基金"，这里的%name%就是识别出来的基金名称。如果匹配上了，但该基金没有配置仓位信息（没有满仓额度配置），则显示红色的基金代码，并且设置该记录无效，出错信息是"%name%匹配到系统中的基金，但该基金没有配置仓位信息"，这里的%name%就是识别出来的基金名称。否则，正常显示基金代码。
   * 基金名称：name，仅作为显示使用，不作为识别的主要依据。需要根据识别出来的内容和系统中已有的基金名称进行模糊匹配，匹配成功则使用系统中对应的基金名称进行显示，匹配失败则使用识别出来的基金名称进行显示。如果基金有常用名字的话，还要和常用名字进行模糊匹配。
   * 交易类型：trade_type（买入/卖出）
   * 交易价格：trade_price，如果匹配上了基金代码并且该基金有配置仓位信息，则要和该基金在该交易日期的价格进行对比，如果识别出来的交易价格和系统中该基金在该日期的价格保留四位小数后不一致，则显示红色的交易价格，并且设置该记录无效，出错信息是"%name%在%date%的交易价格识别为%trade_price%，与系统中该基金在该日期的价格%system_price%不一致"，这里的%name%、%date%、%trade_price%、%system_price%分别是识别出来的基金名称、交易日期、交易价格和系统中该基金在该日期的价格。否则，正常显示交易价格。
   * 基金份额：share，如果匹配上了基金代码并且该基金有配置仓位信息，并且当交易类型为“买入”时，需要校验该值是否和根据识别出来的交易价格，手续费和交易总额计算出来的份额一致，如果不一致则显示红色的基金份额，并且设置该记录无效，出错信息是"%name%在%date%的交易份额识别为%share%，与根据交易价格%trade_price%和交易总额%total_amount%计算出来的份额%calculated_share%不一致"，这里的%name%、%date%、%share%、%trade_price%、%total_amount%、%calculated_share%分别是识别出来的基金名称、交易日期、基金份额、交易价格、交易总额和根据交易价格和交易总额计算出来的基金份额。否则，正常显示基金份额。当交易类型为“卖出”时，不进行上述校验。校验公式为：calculated_share = (total_amount - fee) / trade_price。
   * 手续费：fee
   * 交易总额：total_amount。如果匹配上了基金代码并且该基金有配置仓位信息，并且当交易类型为“卖出”时，需要校验该值是否和根据识别出来的交易价格，手续费和基金份额计算出来的交易总额一致，如果不一致则显示红色的交易总额，并且设置该记录无效，出错信息是"%name%在%date%的交易总额识别为%total_amount%，与根据交易价格%trade_price%、手续费%fee%和基金份额%share%计算出来的交易总额%calculated_total_amount%不一致"，这里的%name%、%date%、%total_amount%、%trade_price%、%fee%、%share%、%calculated_total_amount%分别是识别出来的基金名称、交易日期、交易总额、交易价格、手续费、基金份额和根据交易价格、手续费和基金份额计算出来的交易总额。当交易类型为“买入”时，不进行上述校验。校验公式为：calculated_total_amount = share * trade_price - fee。
   * 是否有效：is_valid，如果上述任何一个校验不通过，则该交易记录的是否有效为false（显示为一个红色的小叉），否则为true（显示为一个绿色的小勾）。无效的交易记录在最后的操作中会被过滤掉，不进行添加或更新操作。图标的hovertip显示具体的错误信息。表头文字为"有效性"。
   * 多选按钮：用户可以选择要添加的交易记录。无效的交易记录默认不选中，且用户无法选中。表头提供全选和反选按钮。
* 表格提供一个总计行，显示成功识别的交易记录数量和失败识别的图片数量。表格最多同时显示10行，超过10行时，使用滚动条显示。滚动条的滚动操作不影响表头和总计行的显示，且滚动条的出现不会遮挡表格内的内容。表格应该定高，不会因为行数的变化而改变表格的高度。
* 对于识别失败的图片，在结果窗口表格下方显示一个错误信息区域，以文本的形式显示识别或处理失败的图片名称（仅文件名，不需要路径），以及对应的错误信息（如无法识别出基金代码、交易份额等信息，或者前面出现的信息佩配不上等错误信息）。如果有多条失败信息，则显示多条错误信息，以换行分割。每条错误信息前面显示一个警告图标，以红色字体显示错误信息文本。
* 结果窗口底部显示一个"确认"按钮，用户点击后根据选择的基金信息进行添加，操作完成后，关闭窗口。
* 结果窗口右上角有一个关闭按钮，用户点击后关闭窗口，不进行任何添加操作。
* 当不是通过确认按钮关闭窗口，并且表格中有有效的交易记录时，系统弹出确认提示："当前有识别成功的交易记录，确定要关闭吗？"，用户选择"确认关闭"则关闭窗口，数据丢弃；用户选择"取消"则保持窗口打开，数据保留。

### 图形识别细节
* 系统使用图像识别技术（如OCR）来识别图片中的文本信息。
* 需要识别出以下的信息：
  1. 基金名称：例如"南方有色金属ETF联接C"，可以从“买入产品”或”卖出产品“字段中提取
  2. 操作："买入"/"卖出"，可以从上方“买入成功”或“卖出成功”中提取
  3. 金额：买入操作时，可以从上方“买入成功”上面提取. 卖出操作时，从“到账金额”字段提取
  4. 确认份额：例如 1022.26
  5. 确认净值：例如 4.8838
  6. 手续费：例如 7.49
  7. 交易时间：可以从“买入时间”或“卖出时间”中提取，例如 2026-04-24 14：53：26
* 如果不能识别上述信息中的任意一项，则认为该图片识别失败。


### 基金模糊匹配逻辑
因为OCR识别出来的基金名称可能和系统中已有的基金名称不完全一致，所以需要进行模糊匹配。匹配逻辑如下：
1. 首先根据识别出来的基金名称与系统中的基金名称进行模糊匹配，匹配算法使用编辑距离（Levenshtein距离）算法，找到最相似的基金名称，计算相似度得分。
2. 同时，如果基金配置了常用名称（displayName），则用识别出来的基金名称与常用名称进行模糊匹配，计算相似度得分。
3. 取两个相似度得分中的最高值，如果该值高于系统设定的阈值，则认为匹配成功，使用系统中对应的基金名称作为显示的基金名称。
4. 否则认为匹配失败，使用识别出来的基金名称作为显示的基金名称，并将该交易记录标记为无效。

### 添加交易操作
* 当用户点击结果窗口中的"确认"按钮后，系统根据用户选择的交易信息进行添加操作。
* 系统将选中的基金交易信息根据交易日期，基金代码等信息添加到系统中对应基金的交易记录里。用到的信息与通过界面添加单条交易记录时需要的信息相同。
